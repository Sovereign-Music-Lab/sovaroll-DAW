# SovaRoll 사용 설명서

[English](MANUAL.en.md) · [프로젝트](../README.ko.md) · [CLI 가이드](CLI-GUIDE.ko.md) · [CLI 전체 도움말](CLI.md) · [개발 노트](DEVELOPMENT.ko.md)

개발 버전 0.129.0 기준입니다. 화면은 대화상자까지 한국어·영어로 전환할 수 있습니다. 여러 조각을 이어 만든 일부 실행 중 메시지는 드물게 한국어로 남을 수 있으니 `node scripts/i18n-coverage.mjs` 결과와 함께 알려 주세요. 검증 환경은 macOS와 Chrome입니다. 다른 운영체제·브라우저는 별도 검증이 필요하며 선택적 native MIDI는 macOS 전용입니다.

## 1. 설치와 첫 실행

Node.js 22 이상과 Git을 설치하고 터미널에서 실행합니다.

```sh
node --version
git --version
git clone https://github.com/Sovereign-Music-Lab/sovaroll-DAW.git
cd sovaroll-DAW
npm start
```

DAW 실행에 `npm install`, LLM, 가중치, 계정, 다른 저장소는 필요하지 않습니다. 터미널을 켜 둔 상태로 [http://127.0.0.1:4317](http://127.0.0.1:4317)을 엽니다. 처음에는 `sessions/First-Light.newdaw.json`에 짧은 합성 데모를 만듭니다. 파일이 이미 있으면 새 데모로 덮어쓰지 않고 엽니다.

종료하려면 터미널에서 **Ctrl+C**를 누릅니다. 브라우저 탭만 닫으면 서버는 계속 실행됩니다. 현재 버전은 로컬 사용을 위한 앱이며 여러 사용자를 위한 호스팅 서비스가 아닙니다.

4317을 사용 중이면 `npm start -- --port 4318`로 실행하고 [4318 포트](http://127.0.0.1:4318)를 엽니다. 해당 서버에 연결하는 CLI에는 `--url http://127.0.0.1:4318`을 붙입니다. 다른 작업의 서버를 임의로 종료하지 않습니다.

## 2. 빈 프로젝트 만들기

저장소 루트에서 macOS/Linux 셸 기준으로 실행합니다.

```sh
mkdir -p "$HOME/Music/SovaRoll/My-Song"
node src/cli.mjs init "$HOME/Music/SovaRoll/My-Song/My-Song.newdaw.json"
node src/cli.mjs serve --project "$HOME/Music/SovaRoll/My-Song/My-Song.newdaw.json" --port 4318
```

`init`은 기존 파일을 덮어쓰지 않습니다. 선택한 포트로 브라우저를 엽니다. 프로젝트를 앱 폴더 밖에 두면 업데이트와 앱 삭제가 쉬워집니다. 다른 셸에서는 적합한 절대 경로를 사용합니다.

**프로젝트 열기** 창에서도 생성·열기를 제공합니다. 대상 경로와 활성 프로젝트를 확인합니다. 여러 프로젝트를 열 수 있지만 편집·재생은 활성 문서에 적용됩니다. 열기·활성화·닫기는 구분되며, Untitled 작업은 처음 저장할 때 이름과 경로가 필요합니다.

## 3. 화면 구성

상단의 **English / 한국어** 선택기에서 화면 언어를 바꿉니다. 선택은 현재 브라우저에 저장되어 새로고침 후에도 유지되며 프로젝트는 변경하지 않습니다. 영어 모드는 `public/i18n-dictionary.mjs`로 모든 화면·대화상자·툴팁·상태 메시지를 번역하고, 한국어로 돌아가면 원문을 복원합니다. 트랙·클립·파일 이름 같은 프로젝트 데이터는 번역하지 않습니다. Audio Unit 대화상자는 컨트롤·범위·파라미터 메타데이터·렌더/미리 듣기/가져오기 상태를 번역하지만 구성요소 이름·keyPath·서버/플러그인 오류는 원본으로 표시합니다. 편집 이력과 자동백업 대화상자도 컨트롤·작업 이름·경계·저장 상태·목록을 번역하며 명령 ID·시각·경고는 식별 가능하게 유지합니다.

| 표시 | 용도 |
|---|---|
| 프로젝트 열기 | 프로젝트 생성·열기·활성 문서 선택 |
| 저장·버전 | 저장, 다른 이름, 번호 버전과 되돌리기 |
| 편집 이력 | 편집과 Undo/Redo 위치 |
| 자동백업 | 자동 백업 설정과 복구 |
| 미디어 풀 | 원본 미디어와 누락 상태 |
| 백업 ZIP | 프로젝트·미디어 묶음 내려받기 |
| 프로젝트 JSON | 프로젝트 설명만 내려받기; 오디오 미포함 |
| 가져오기 | WAV·AIFF·MIDI 가져오기 |
| MIDI 내보내기 | 편집 가능한 MIDI 출력 |
| 믹스 WAV 내보내기 | 오디오 렌더·내보내기 |
| 처음으로·재생·정지 | 커서와 재생 제어 |
| 반복 | 로케이터 구간 반복 |
| 도움말 | 앱 내 도움말 |

편곡 화면에는 트랙과 클립이 표시됩니다. MIDI 클립을 선택하면 피아노롤에서 노트를 편집합니다. Inspector는 선택한 대상을 수정합니다. 일부 도구는 접힌 메뉴 안에 있거나 해당 대상을 선택했을 때만 나타납니다.

## 4. 매일 사용하는 순서

1. 원하는 프로젝트로 서버를 실행하고 이름·경로를 확인합니다.
2. 큰 편집 전에는 저장·버전·백업을 만들고 미디어 누락을 확인합니다.
3. MIDI 트랙·파트를 만들거나 MIDI·오디오를 가져옵니다.
4. 노트·클립을 편집하고 프레이즈를 확인하며 Undo로 비교합니다.
5. 트랙을 조절하고 듣습니다. 믹스를 출력해도 MIDI와 원본 오디오는 보존합니다.
6. 명시적으로 저장하고 필요한 교환 파일과 프로젝트·미디어 백업을 만듭니다.
7. 재생과 서버를 종료하고 전체 프로젝트 폴더를 보관합니다.

편집은 자동으로 저장되지만 **명시적 Save**는 Revert·버전 작업의 기준점을 만듭니다. 두 개념은 다릅니다. 렌더된 WAV는 당시의 결과이며 나중에 MIDI를 고쳐도 자동으로 바뀌지 않습니다.

## 5. MIDI와 편곡

MIDI 파트를 선택한 뒤 피아노롤 빈 칸을 클릭해 노트를 넣습니다. 드래그로 시간·음높이를 옮기고 Inspector에서 길이·벨로시티를 정확히 수정합니다. 여러 노트를 선택해 전조·퀀타이즈·벨로시티·레가토 등을 적용할 수 있습니다. 일괄 편집 전에 선택 범위를 확인합니다.

피아노롤에 초점이 있을 때 Cmd/Ctrl+A·C·V로 선택·복사·붙여넣기를 합니다. 눈금자로 커서를 옮긴 뒤 붙여넣습니다. 텍스트 입력칸에서는 일반 텍스트 단축키로 작동합니다. Cmd/Ctrl+Z는 실행 취소, Cmd/Ctrl+Shift+Z는 다시 실행입니다. 버튼과 CLI 편집도 같은 실행 취소 이력을 사용합니다.

클립 도구로 이동·분할·반복·복사 작업을 합니다. 폴더와 트랙으로 편곡을 정리하고, 로케이터로 작업·출력 구간을 정하며, 마커로 위치와 범위를 표시합니다. 시간·스냅은 음악 시간과 초·샘플·프레임을 구분합니다. 표시 단위와 저장 단위가 다를 수 있으므로 자동화에서는 명령 스키마의 tick/sample 필드를 확인합니다.

컨트롤러 레인은 편집 가능한 값과 곡선을 보관합니다. MIDI로 내보낼 때 지원 곡선을 이벤트로 변환하고 프로젝트 JSON에는 편집 표현을 유지합니다. MIDI 수정자는 원본 노트를 보존하며 재생·출력에 적용될 수 있습니다. Freeze는 지원 변환을 실제 이벤트로 확정하는 작업이므로 범위와 Undo를 확인합니다.

내장 oscillator는 프리뷰 음원입니다. MIDI 파일에 보존한 메시지라도 원래 악기의 패치·프레셔·SysEx 소리를 그대로 재현하지 않을 수 있습니다.

## 6. 오디오 가져오기·편집·녹음

**가져오기**에서 WAV·AIFF·MIDI를 고르고 경고와 배치 옵션을 확인합니다. 오디오는 관리하는 원본 에셋을 참조하므로 `assets/`를 함께 보관합니다. 이동·trim·split·gain·fade·polarity 등 지원 편집은 원본을 보존합니다. 오디오 통계는 기술적 수치이며 청음을 대신하지 않습니다.

오디오 녹음에는 브라우저 마이크 권한이 필요합니다. 입력 장치·대상·녹음·모니터링 옵션을 정하고 녹음 후 클립을 확인합니다. 먼저 짧게 시험하고, 모니터링 시에는 피드백을 피하도록 헤드폰을 사용합니다. 카운트인·반주 재생에는 설정과 타이밍 한계가 있습니다. 공개 자동 검증은 가짜 마이크를 사용했으므로 실제 지연·음질은 직접 확인해야 합니다.

Web MIDI 입력은 연결 버튼에서 브라우저 권한을 요청합니다. 장치와 캡처 설정을 고르고 짧은 테이크로 노트·컨트롤러를 확인합니다. 저장 실패나 활성 문서 변경이 생기면 테이크 JSON·복구 기록을 보존합니다. 브라우저 안의 테이크 복구 자료는 내보낸 MIDI·프로젝트 백업과 별도입니다.

선택적 오프라인 타임 스트레치는 외부 **FFmpeg** 실행 파일을 사용합니다. PATH에 설치하거나 `NEWDAW_FFMPEG`를 실행 파일의 절대 경로로 설정합니다. SovaRoll이 내려받거나 함께 배포하지 않으며 기본 편집·재생에는 필요하지 않습니다.

## 7. 재생과 믹싱

Play/Stop 또는 텍스트 입력 밖에서 Space를 사용합니다. 브라우저가 렌더 스냅샷을 준비하며, 편집하면 이전 프리뷰를 현재 믹스로 오해하지 않도록 재생이 멈출 수 있습니다. 눈금자로 탐색하고 로케이터로 Cycle 구간을 정합니다.

트랙 gain·pan·mute·solo와 마스터 gain을 조절합니다. 내보내기 전에 mute/solo를 확인하고 적당한 음량으로 들으며 과부하를 살핍니다. 현재는 저지연 네이티브 녹음 엔진이나 외부 VST/AU 악기 호스트를 제공하지 않습니다.

선택적 macOS MIDI 출력은 시스템 Swift 도구가 필요합니다.

```sh
node scripts/build-native-midi.mjs
npm run cli -- native-ports
npm run cli -- native-status
```

**MIDI 출력**에서 실제 대상·채널을 설정하고 라우팅을 확인합니다. native 모드는 **MIDI만 전송**하고 오디오 클립을 동기 재생하지 않습니다. CLI의 `native-stop`, `midi-reset`도 사용할 수 있습니다. 브리지는 선택 사항이며 모델과 무관합니다.

## 8. 저장·복구·작업 이동

Cmd/Ctrl+S 또는 **저장·버전**을 사용합니다. Save As·새 버전 저장은 활성 경로를 바꿀 수 있으므로 다음 실행 전에 확인합니다. 프로젝트 JSON, `assets/`, 이력·저장 부속 파일과 백업·복구 폴더를 함께 보관합니다. `.bak`, `.history.json`, `.saved.json`은 서로 다른 역할이 있으므로 파일 하나만 고르지 말고 폴더 전체를 보관합니다.

미디어 누락은 미디어 풀의 검사·복구로 확인합니다. 정확한 복원은 원본 바이트를 검증합니다. 다른 파일로 교체·재연결하는 작업은 결과를 바꿀 수 있습니다. 원인을 확인하는 동안 기존 프로젝트나 미디어를 삭제하지 않습니다.

기본 서버 실행 중 CLI 예시:

```sh
npm run cli -- document
npm run cli -- history
npm run cli -- assets
npm run cli -- backups
npm run cli -- save
npm run cli -- export-bundle sessions/My-Song-backup.zip
```

다른 서버에는 `--url`을 붙입니다. ZIP은 프로젝트·미디어를 포함하고 JSON만으로는 오디오를 포함하지 않습니다. 묶음은 프로젝트·미디어 이동용이므로 과거 이력과 복구 자료까지 필요하면 원래 폴더 전체도 보존합니다. 복구본을 확인한 뒤 작업본 교체 여부를 정합니다.

## 9. 내보내기

```sh
npm run cli -- render sessions/mix.wav
npm run cli -- export-midi sessions/notes.mid
npm run cli -- render-stems sessions/stems.zip
npm run cli -- export-bundle sessions/project-backup.zip
```

GUI에서도 믹스·MIDI·묶음을 내려받습니다. CLI는 트랙·로케이터 범위, 샘플 형식·레이트, 결정적 디더와 스템 옵션을 제공합니다. 정확한 조합은 [CLI 도움말](CLI.md)과 현재 `--help`를 확인합니다. `--force` 없이는 기존 출력 파일을 덮어쓰지 않습니다. 리비전 비교에는 새 이름을 사용합니다.

MIDI는 음악 이벤트를 담으며 믹싱된 소리, 모든 플러그인 음색·믹서 선택을 담지 않습니다. 다른 DAW로 옮길 때 프로젝트 묶음·믹스·MIDI를 함께 남기는 것이 유용합니다. 형식에 담을 수 없는 정보는 출력 경고를 확인합니다.

현재 **렌더 구간은 꼬리를 포함해 600초**이며 메모리와 파일·묶음 크기 제한이 있습니다. 출력 설정을 정할 때 현재 capability·도움말을 확인하고 필요하면 범위를 나눕니다. 내보내기 성공이 청음 검토를 뜻하지는 않습니다.

서버 없는 오프라인 렌더:

```sh
node src/cli.mjs offline-render /absolute/path/My-Song.newdaw.json /absolute/path/mix.wav
```

## 10. CLI와 로컬 에이전트

```sh
npm run cli -- status
npm run cli -- commands
npm run cli -- command track.add '{"type":"midi","name":"Piano"}' --dry-run
npm run cli -- command track.add '{"type":"midi","name":"Piano"}'
```

예제 ID를 그대로 사용하지 말고 현재 프로젝트에서 반환한 ID를 사용합니다. `--dry-run`은 적용 없이 검증하고, `--revision N`은 다른 편집이 먼저 발생했을 때 거부합니다. batch는 하나의 검증·Undo 단위입니다. 자동 명령 생성 전에 [CLI 도움말](CLI.md)과 현재 스키마를 읽습니다.

Gemma 4는 관리자의 코딩 작업 방침이며 앱에 내장된 채팅·작곡 서버가 아닙니다. 전체 RAG/LoRA–DAW–자율형 작곡–Logic Pro MCP 피드백 순환은 전체 생태계의 개발 방향입니다. [철학](../PHILOSOPHY.ko.md)과 [모델 인계](agent/LOCAL_MODEL.md)를 참고합니다.

## 11. 업데이트와 검증

프로젝트를 저장하고 폴더 전체를 백업한 뒤 서버를 종료합니다. 코드 수정 여부를 확인합니다.

```sh
git status --short
git pull --ff-only
```

pull이 거부되면 로컬 변경을 보존하고 해결합니다. 강제로 초기화하지 않습니다. 이후 선택한 프로젝트를 다시 열어 작은 편집·Undo·짧은 출력을 확인합니다.

개발 검증:

```sh
# Playwright는 사용자 실행에는 선택 사항, 브라우저 검사에는 필요합니다.
npx --yes playwright --version
node scripts/agent/guard.mjs --init
npm run agent:verify:full
npm run test:native
npm run agent:e2e
```

Chrome이 필요합니다. 하네스는 npm 캐시 또는 `NEWDAW_PLAYWRIGHT_MODULE=/absolute/path/to/playwright/index.mjs`에서 Playwright를 찾습니다. 전체 타임 스트레치 테스트에는 FFmpeg가 필요합니다. 테스트는 합성·임시 데이터를 사용합니다. 일부 브라우저·native 경로는 macOS 전용이며 다른 플랫폼에서 같은 검증을 했다고 주장하지 않습니다.

## 12. 문제 해결

| 증상 | 확인할 것 |
|---|---|
| 브라우저 연결 실패 | 터미널 서버 출력, 포트, Node 버전, 서버 실행 유지 |
| 포트 사용 중 | 다른 포트를 고르고 CLI `--url`도 일치시키기 |
| 프리뷰 무음 | 브라우저 오디오·출력 장치, 트랙·마스터, mute/solo, 활성 프로젝트·현재 렌더 |
| MIDI 음색이 다름 | 내장 oscillator는 모든 외부 패치·메시지를 재현하지 않음 |
| 미디어 누락 | 프로젝트·assets 동반 보관, `assets` 명령과 미디어 복구 |
| 오래된 편집 거부 | 최신 리비전·ID를 다시 읽고 변경을 재검토 |
| 타임 스트레치 불가 | 외부 FFmpeg 설치·경로 확인 또는 다른 편집 사용 |
| E2E 차단 | Chrome과 외부 Playwright 경로·캐시 확인 |
| 녹음 실패 | 권한·장치·대상·테이크 복구 기록을 확인하고 짧게 시험 |

## 13. 음악을 보존하며 삭제하기

1. 저장하고 중요한 MIDI·믹스를 내보낸 뒤 전체 프로젝트 폴더를 앱 폴더 밖에 백업합니다.
2. 재생을 멈추고 터미널에서 Ctrl+C로 서버를 종료합니다.
3. 음악이 밖에 있는지 확인한 뒤 복제한 `sovaroll-DAW` 앱 폴더를 휴지통으로 옮깁니다. 기본 `sessions/`는 앱 폴더 안이므로 사용했다면 먼저 복사합니다.
4. 원하면 복구할 테이크를 내보낸 뒤 해당 앱 주소의 브라우저 저장소만 지웁니다. 이 저장소에는 복구 자료와 설정이 있을 수 있으며 지우면 삭제됩니다.
5. Node·Git·Chrome·FFmpeg·Playwright·모델 런타임은 별도 설치 프로그램입니다. 다른 곳에서 쓰지 않을 때만 별도로 제거합니다.

위 시작 명령은 별도 SovaRoll 계정이나 백그라운드 서비스를 설치하지 않습니다. 터미널의 서버 프로세스가 살아 있는 동안 실행됩니다.
