# Product acceptance tracking / 제품 수용 기준 기록

1. Read `docs/agent/REQUIREMENTS.md` and the task card.
2. Preserve FD-01 through FD-30. Add IDs for new requirements; do not merge away unmet criteria.
3. Distinguish implemented, partial, verified, and manual. A test proves only the path it exercises.
4. Record the actual command, test/step, result and limits in `docs/VALIDATION.md` when changing status. Update both development-note language editions if capabilities change.
5. Do not report listening or musical quality from waveform/level checks.
6. Finish only after required verification passes, with real `done --evidence`.

한국어: 요건 ID와 미충족 조건을 유지합니다. 구현과 검증을 구분하고, 상태 변경에는 실제 명령·테스트·결과·한계를 기록합니다. 파형 검사로 청음이나 음악적 품질을 주장하지 않습니다.
